# Auth·BFF 세션 전환 테스트 계획

2026-09-26 목표 설계의 검증 계획이다. 이 문서의 항목은 아직 실행하지 않았다.
이전 테스트 결과는 [과거 실행 기록](../verification-2026-09-24.md)에 보존한다.
새 설계의 근거는 [단일 세션 계약](../session/SESSION_DESIGN.md)이다.

## 구조와 테스트 경계

코어는 가짜 포트·고정 Clock, 어댑터는 실제 PostgreSQL·Redis/Valkey, HTTP는 Auth·BFF
독립 인스턴스로 확인한다. Google은 테스트 HTTP/JWK 서버와 실제 브라우저 검증을 구분한다.
ArchUnit의 코어 의존 규칙과 기존 계정·OAuth 회귀를 유지한다.

## 계정 저장

UUID v7·복합 PK 충돌 롤백·재조회, 표시 이름 보존·이메일 갱신, DB 커밋 후 세션 생성
실패 시 계정 유지를 확인한다. 오류가 기존 계정을 삭제하지 않아야 한다.

### 마이그레이션 실행 방식

테스트 DB도 Flyway로 생성하고 Hibernate validate로 확인한다.
새 DB의 V1→V2와 V1 기반 업그레이드, V1 체크섬 보존, 재실행 시 중복 변경 방지를 검사한다.
기존 migration 파일을 세션 전환 때문에 수정하지 않는다.

## OAuth 상태

브라우저 연결·state·만료와 일회성 소비, 동시 콜백 중 한 번 소비, PKCE·nonce·Google
ID Token의 신원 검증 실패를 확인한다. 실패 시 계정·세션 생성이 진행되면 안 된다.
login_request_consumed의 true·false·null을 보존한다.

## 세션 생성과 인증

- ID가 32바이트 난수의 정규 Base64URL이며 로그인마다 달라지고 사용자 정보가 포함되지 않는지 확인한다.
- Redis에 원문 대신 SHA-256 해시를 저장하고 해시 자체로는 인증할 수 없는지 확인한다.
- 새 로그인에서 두 인덱스·동일 TTL이 생성되고 ID·expires_at이 새 내부 응답과 맞는지 확인한다.
- 기존 인덱스가 남아도 현재 사용자 인덱스 불일치로 이전 로그인이 거절되는지 확인한다.
- 쿠키 없음·중복·잘못된 길이·정규 인코딩 오류와 손상 JSON·미지원 버전·TTL 없음의 오류를 구분한다.
- 첫 GET 뒤 로그인·폐기를 실행해도 스크립트 재검증이 이전 세션을 허용하지 않는지 확인한다.

## 활동과 만료

- 마지막 인증 활동 전후의 정확한 14일 경계를 저장소 시각으로 확인한다.
- 만료 전 활동은 같은 ID로 두 키의 만료를 연장하고 만료 이후 요청은 상태를 생성하지 않는지 확인한다.
- 공개 경로·사전 요청·CSRF 실패·인증 실패·로그아웃은 연장하지 않는지 확인한다.
- 인증 성공 후 도메인 오류가 발생해도 활동은 반영되는지 확인한다.
- 동시 활동에서 만료가 정상적으로 연장되고 최초 로그인 기준 상한을 임의로 적용하지 않는지 확인한다.
- 실제 쿠키 Max-Age도 연장되는지, 응답 지연·서버 시각 차이·헤더 생성 시 이미 지난 만료를 처리하는지 확인한다.

## 동시성과 폐기

독립 연결·BFF 두 인스턴스로 다음 양쪽 실행 순서를 확인한다.

| 경쟁 | 기대 |
|---|---|
| 로그인·로그인 | 마지막 적용 한 세션만 유효 |
| 이전 활동·새 로그인 | 이전 ID로 새 세션 인증·연장 불가 |
| 활동·폐기 | 삭제된 세션 재생성 없음 |
| 이전 ID 폐기·새 로그인 | 새 세션 유지 |
| 같은 ID의 여러 활동 | 정상 동시 사용·연장 |
| 동일 ID 반복 폐기 | 사용 불가 상태로 완료 |

폐기의 부재·만료·다른 활성 ID·형식 오류·재시도 중 새 로그인과 최대 예산을 확인한다.
프론트에서는 늦은 Set-Cookie와 로그아웃 삭제 헤더가 새 로그인에 미치는 영향을 실제 브라우저로 검증한다.

## 오류 처리

- 저장소 생성·검증/연장·폐기의 명령 미실행·응답 유실·ACL 오류·부분 쓰기 실패를 주입한다.
- 결과 불명에서 인증 성공·쿠키 연장·내부 호출이 발생하지 않는지 확인한다.
- 실패한 로그인에서 ID 미반환, 폐기 미확인에서 외부 결과 구분과 쿠키 삭제 헤더를 확인한다.
- 각 JSON 오류·HTTP 상태·code·next_action이 계약과 맞고 민감값이 노출되지 않는지 확인한다.
- 연결 초기화 포함 500ms, 금지된 자동 재시도·replay, Auth 폐기 예외 예산을 확인한다.

## ACL과 통합

실제 운영 대상 Redis·Valkey 버전에서 BFF의 GET·검증/연장 스크립트 성공과 SET·DEL·
다른 키 거절을 확인한다. Auth 계정과 BFF 계정을 분리하고 프로토콜 초기화까지 검증한다.
전체 흐름은 Google 준비·콜백·본인 계정·Content·다른 로그인 차단·활동 연장·로그아웃이다.
브라우저·프론트·운영 접근 제한 검증을 따로 기록하며 기존 테스트 통과로 대체하지 않는다.
