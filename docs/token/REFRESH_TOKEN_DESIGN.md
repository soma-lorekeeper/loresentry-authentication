# Auth Refresh Token 설계

**사용자별 활성 세션 하나에 현재 RT 식별자와 만료를 함께 저장한다.**
새 로그인은 기존 세션을 교체한다. 상세 공유 스키마·동시성·전환 기준은
[단일 로그인 세션 설계](SINGLE_SESSION_DESIGN.md), 토큰 규격은 [JWT 설계](JWT_DESIGN.md)를 따른다.
2026-09-24 Auth 구현과 테스트에 반영했으며 BFF 연동과 운영 배포는 별도다.

## 상태 저장

| 항목 | 구현 계약 |
|---|---|
| 키 | `auth:session:{userId}` |
| 값 | UTF-8 JSON String: `schema_version=1`, `sid`, `refresh_jti`, `refresh_expires_at` |
| 만료 | RT `exp`의 UTC epoch 초. 최종 `SET PXAT`에 밀리초로 변환하여 지정 |
| 저장하지 않는 값 | AT·RT 원문, 기기 목록, 이전 RT 복구 데이터 |

`SessionStore`가 교체·조건부 갱신·조건부 폐기를 정의하고 `RedisSessionStore`가
`redis/session.lua`를 `EVAL`로 한 번 실행한다. Lua는 Redis의 `TIME`으로 만료를 검사한다.
검사를 먼저 끝내고 마지막에 `SET PXAT` 또는 `DEL` 하나를 실행한다.

## 재발급과 폐기

1. RT의 JWT와 필수 `sid`를 검증한다.
2. 같은 sid의 새 AT·RT를 먼저 서명한다.
3. 저장된 sid·현재 RT jti·만료가 입력 RT와 일치하고 미만료일 때만 JSON과 만료를 교체한다.
4. 교체 성공을 확인한 뒤 새 토큰 쌍을 반환한다.

동일 RT의 동시 갱신 중 하나만 성공한다. 부재·만료·이전 sid·이전 jti는
`401 REFRESH_REJECTED`이며 실패 요청은 상태를 변경하지 않는다.
갱신 중 키를 먼저 삭제하지 않고, 삭제된 세션을 재생성하지 않는다.

폐기는 검증한 **미만료 RT의 sid**가 현재 세션과 같을 때만 수행한다.
현재 RT jti와의 일치는 요구하지 않아 회전 전의 미만료 RT로도 같은 세션을 로그아웃할 수 있다.
키 부재·다른 sid·이미 만료된 RT는 삭제 없이 `204`다. 위조·필수 클레임 누락은 거절한다.

## 여러 기기 로그인

계정당 하나의 로그인 세션을 허용한다. 새 로그인은 새 sid로 기존 레코드를 교체하며
이전 RT는 거절된다. 이전 AT의 실제 API 접근 차단은 BFF의 활성 세션 조회 구현을 필요로 한다.
같은 브라우저 프로필의 탭은 쿠키를 공유한다. 물리 기기 식별이나 복제 토큰 감지는 하지 않는다.

## 만료 연장

성공한 재발급 시 RT 만료를 새 발급 시각부터 14일로 계산한다. sid는 유지한다.
최초 로그인 기준 최대 기간은 두지 않는다. BFF의 일반 GET은 만료를 연장하지 않는다.
JWT의 30초 시계 오차 허용과 달리 저장소 만료에는 유예가 없다.

## 재발급 응답 유실

명령 미실행 확인은 `503 REFRESH_UNAVAILABLE/RETRY_LATER`, 결과 불명은
`503 REFRESH_OUTCOME_UNKNOWN/RELOGIN`이다. 자동 재시도·이전 RT 복구·결과 재전달은 하지 않는다.
성공한 갱신의 응답을 잃으면 이전 RT로 재시도해도 거절된다.
별도 새 RT 저장 단계가 없어 `REFRESH_SAVE_FAILED`는 제거했다.
서명 실패는 저장 전에 `500 INTERNAL_ERROR`, 손상된 레코드도 변경 없이 같은 500으로 처리한다.

## 로그아웃 폐기 실패

일시적 저장소 장애일 때 요청 안에서만 제한적으로 재시도한다.

| 항목 | 제한 |
|---|---|
| 시도 | 최초 포함 최대 3회 |
| 대기 | 첫 재시도 전 100ms, 두 번째 재시도 전 200ms |
| 명령 | 연결 획득을 포함해 최대 500ms |
| 전체 삭제 단계 | 대기를 포함해 최대 2초 |

매번 동일한 sid·입력 RT 만료 조건을 적용한다. 대기 중 새 로그인이 생겨도 그 세션은
삭제하지 않으며, RT가 만료되면 추가 삭제를 멈춘다. Lua도 실제 실행 시 만료를 다시 확인한다.
최종 미확인은 `503 REVOCATION_UNCONFIRMED`이며 백그라운드 재시도는 하지 않는다.
손상된 데이터는 재시도 없이 500으로 처리한다. 이 재시도는 로그인·갱신에는 적용하지 않는다.
브라우저 쿠키 처리는 [BFF 로그아웃 계약](../../../loresentry-gateway/docs/auth/LOGOUT_FLOW.md)을 따른다.
